# Внедрение Firebase: пошаговый план

Речь о том, чтобы наш веб-интерфейс (он же внутри APK на GeckoView) брал данные
из Firebase: вход, чаты, сообщения, прочтения, «печатает…», «в сети», файлы.
Свой сервер на VPS остаётся как резерв и как второй бэкенд.

Сейчас клиент ходит в `api.js` → `HttpBackend` (наш Python на VPS).
Задача — добавить `FirebaseBackend` с тем же интерфейсом, чтобы **экраны и стили
не менялись вообще**.

---

## 0. Что нужно от вас (15 минут)

1. Проект в `console.firebase.google.com` (имя `massa`).
2. Authentication → Email/Password → включить.
3. Realtime Database → создать (регион `europe-west1`, locked mode).
4. Storage → создать (production mode).
5. Добавить Web-приложение → скопировать `firebaseConfig`
   (`apiKey`, `authDomain`, `databaseURL`, `projectId`, `storageBucket`, `appId`).
6. Добавить Android-приложение `app.massa` → скачать `google-services.json`.
7. Вставить правила из [`firebase/database.rules.json`](../firebase/database.rules.json)
   и [`firebase/storage.rules`](../firebase/storage.rules).

Без этого шага дальше двигаться нельзя: нужны `databaseURL` и ключи.

---

## 1. Подключение SDK (0,5 дня)

1. Кладём в `public/` файл `firebase-config.js` с объектом конфигурации
   (он не секретный, но в git не кладём — `.gitignore`).
2. Firebase JS SDK подключаем **локально**, а не с CDN: скачиваем нужные модули
   (`firebase-app.js`, `firebase-auth.js`, `firebase-database.js`,
   `firebase-storage.js`) в `public/vendor/firebase/`, потому что интерфейс должен
   работать без интернета и без внешних запросов.
3. `index.html`: подключаем SDK до `api.js`.

Проверка: в консоли браузера `firebase.app().options.projectId` отдаёт наш проект.

---

## 2. Новый слой данных `firebase.js` (1,5–2 дня)

Пишем объект `FirebaseBackend` с методами, которые уже вызывает интерфейс:

| Метод | Что делает в Firebase |
|---|---|
| `signIn(email, pass)` | `signInWithEmailAndPassword` |
| `signUp(email, pass)` | `createUserWithEmailAndPassword` + запись `users/{uid}` |
| `logout()` | `signOut` |
| `me()` | текущий пользователь + `users/{uid}` |
| `sync()` | `get()` по `chats` моего uid, затем `messages` по каждому чату |
| `sendMessage(chatId, text, replyTo)` | `push()` в `messages/{chatId}` + обновление `chats/{chatId}/last` |
| `markRead(chatId)` | `reads/{chatId}/{uid} = now` |
| `sendFile(chatId, file)` | upload в Storage → `push()` сообщения с `attachment` |
| `fileUrl(id)` | `getDownloadURL` |
| `presence(chatId, typing)` | `presence/{uid}` + `typing/{chatId}/{uid}` |
| `getMembers(chatId)` | `chats/{chatId}/members` → `users/*` |
| `setChatAvatar(chatId, dataUrl)` | Storage → `chats/{chatId}/photo` |
| `searchAll(q)` | `users` по имени/почте + мои чаты |
| `addChat(uid)` | создание `chats/{id}` с детерминированным ключом для личных |
| `createGroup(name, ids)` | новый `chats/{id}` типа `group` |
| `joinGroup` / `leaveGroup` | правка `members` |

Тот же контракт — интерфейс не трогаем. Переключение:

```js
// api.js
var BACKEND = localStorage.getItem('massa.backend') || 'firebase';
```

Проверка: вход, список чатов, отправка, прочтения — на Firebase, экраны те же.

---

## 3. Реальное время вместо опроса (0,5 дня)

`sync()` остаётся для первого кадра, дальше подписки:

- `onChildAdded(messages/{chatId})` — новые сообщения;
- `onValue(reads/{chatId})` — «прочитано» без перезагрузки;
- `onValue(typing/{chatId})` — «печатает…»;
- `onValue(presence)` — «в сети»;
- `onDisconnect()` — сервер сам поставит офлайн и снесёт «печатает…».

Интерфейсу отдаём те же события, что сейчас приходят из опроса: `applySync`,
`updatePresenceUI`, `renderConversation`. Код экранов не меняется.

---

## 4. Офлайн (1 день)

1. `firebase.database().setPersistenceEnabled(true)` (в v9 модульном может
   отсутствовать — тогда берём compat-сборку SDK).
2. Интерфейс уже в APK, данные Firebase кэшируются — после перезапуска без сети
   показываем последний кэш.
3. Отправка в офлайне: `push()` пишет локально и досылает при сети; в UI
   показываем «отправляется», потом «отправлено».
4. Проверка: авиарежим → открыть чат → написать → включить сеть → сообщение ушло.

---

## 5. Файлы (0,5–1 день)

- загрузка: `uploadBytesResumable` в `chats/{chatId}/{uuid}`;
- прогресс и отмена в интерфейсе предпросмотра (он уже есть);
- при обрыве — продолжение с того же места (возобновляемая загрузка);
- в сообщении храним `attachment: {path, name, size, mime}`;
- показ: `getDownloadURL` + кэш ссылок в IndexedDB.

Ограничение: правила Storage не умеют проверять участника чата из RTDB,
поэтому чтение разрешено авторизованным, а пути — неугадываемые UUID.
Для MVP нормально; в проде — Cloud Functions с подписанными ссылками.

---

## 6. Правила и проверка безопасности (0,5 дня)

1. Вставляем правила из `firebase/`.
2. В Rules Playground проверяем три случая:
   - чужой чат читать нельзя;
   - писать в `messages` можно только от своего `senderId`;
   - текст длиннее 4096 символов отклоняется.
3. App Check (Play Integrity) — по желанию, после основной работы.

---

## 7. Переключатель бэкендов и резерв (0,5 дня)

- в настройках (или через `?backend=vps`) можно вернуть наш Python-сервер;
- при старте — быстрая проверка доступности Firebase (таймаут 2–3 с);
- недоступен → переключаемся на VPS и показываем «ограниченный режим»;
- VPS при этом продолжает хостить интерфейс, раздавать APK и держать бэкапы.

---

## 8. Порядок и сроки

| Шаг | Работа | Время |
|---|---|---|
| 0 | Конфиг Firebase от вас | 15 мин |
| 1 | SDK локально, config, подключение | 0,5 дня |
| 2 | `FirebaseBackend`: вход, чаты, сообщения, прочтения | 1,5–2 дня |
| 3 | Реальное время: подписки, `onDisconnect` | 0,5 дня |
| 4 | Офлайн, очередь отправки | 1 день |
| 5 | Файлы в Storage | 0,5–1 день |
| 6 | Правила и проверки | 0,5 дня |
| 7 | Переключатель и резерв | 0,5 дня |
| 8 | Проверка на телефоне, сборка APK | 0,5 дня |

Итого **5–6 рабочих дней**, по вечерам — около двух недель.

---

## 9. Что проверяем в конце

- регистрация и вход через Firebase, сессия живёт после перезапуска;
- сообщение доходит на второе устройство мгновенно;
- «прочитано» и «печатает…» обновляются без перезагрузки;
- «в сети» пропадает через 15 секунд после закрытия приложения;
- фото уходит в Storage и показывается в чате;
- авиарежим: интерфейс открывается, история видна, отправка досылается;
- правила: чужой чат недоступен;
- переключение на VPS-бэкенд работает.

---

## 10. Риски

| Риск | Что делаем |
|---|---|
| Бесплатный Spark: 100 подключений, 1 ГБ файлов | хватает с запасом; при росте — Blaze |
| Старые пароли не переносятся (PBKDF2 у нас) | перерегистрация или Admin SDK со сбросом |
| SDK тянет много кода | берём только нужные модули, кладём локально |
| Firebase недоступен из сети пользователя | автопереключение на VPS-бэкенд |
| Две базы рассинхронизируются | VPS-режим только как резерв, без параллельной записи |
