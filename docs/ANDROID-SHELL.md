# Оболочка APK на GeckoView

Решение: приложение — Kotlin-оболочка с движком **GeckoView** (Mozilla), внутри —
наш веб-интерфейс, данные — Firebase. Интерфейс не меняется.

---

## 1. Почему GeckoView (и чем платим)

**Плюсы**

- движок едет внутри APK: одинаковый вид на любом Android, независимо от того,
  обновлялся ли системный WebView;
- современный CSS работает всегда — `color-mix()`, `dvh`, `aspect-ratio`,
  `backdrop-filter`, `@property`;
- minSdk 21, то есть Android 6 покрыт;
- Mozilla-движок, привычный по Firefox.

**Плата**

- APK вырастает до **60–90 МБ на архитектуру** (внутри `libxul.so`);
  с ABI split (`arm64-v8a`, `armeabi-v7a`) это два APK по 40–60 МБ;
- отладка через `about:debugging`, а не Chrome DevTools;
- меньше примеров и статей, чем по WebView.

---

## 2. Как грузить наш интерфейс из APK

Три варианта, порядок предпочтения:

1. **Локальный сервер внутри приложения.** Крошечный HTTP-сервер на
   `127.0.0.1` (несколько десятков строк на Kotlin), раздаёт файлы из `assets/`.
   GeckoView открывает `http://127.0.0.1:PORT/index.html`.
   Это «secure context»: работают `localStorage`, `IndexedDB`, `service worker`,
   как на обычном сайте. Самый надёжный путь.
2. **`resource://android/assets/...`** — если в выбранной версии GeckoView
   поддерживается; проверить в спайке.
3. **`file:///android_asset/...`** — не рекомендуется: у `file://` урезаны
   хранилища, service worker не зарегистрируется.

Для офлайна это и есть решение: интерфейс всегда локальный, сеть нужна только
для данных.

---

## 3. Что должна уметь оболочка

| Возможность | Как в GeckoView |
|---|---|
| Открыть интерфейс | `GeckoSession.loadUri(...)` + `GeckoView.setSession(...)` |
| Кнопка «назад» | `session.goBack()` или выход из приложения |
| Выбор фото и камеры | `PromptDelegate.onFilePrompt` + `ActivityResultContracts` |
| Разрешения камеры/микрофона | `PermissionDelegate.onMediaPermissionRequest` |
| Скачивание файлов из чата | `ContentDelegate.onExternalResponse` / прямой `DownloadManager` |
| Отладка | `GeckoRuntimeSettings.remoteDebuggingEnabled = true` + `about:debugging` |
| Сохранение сессии и кэша | профиль GeckoView в `filesDir`, чистится по желанию |
| Полноэкранное видео | `ContentDelegate.onFullScreen` (если понадобится) |
| Загрузка файлов (докачка) | Firebase Storage resumable upload — см. §5 |

## 4. Структура проекта

```
massa-android/
  app/
    src/main/
      java/app/massa/
        MainActivity.kt        GeckoView, локальный сервер, «назад», сплэш
        AssetsServer.kt        раздача assets по http://127.0.0.1
        FilePicker.kt          камера и галерея
      assets/web/              наш index.html, styles.css, app.js, api.js
      res/                     иконка, тема, сплэш
      AndroidManifest.xml
    build.gradle.kts
```

Внешний вид приложения: тёмно-серый сплэш с надписью MASSA, дальше — наш
интерфейс без изменений.

## 5. Про докачку файлов (то, что нравится в Firefox)

В Firefox «докачка» — это менеджер загрузок браузера. В нашем случае аналог
делает Firebase Storage: у него **возобновляемая загрузка** (resumable upload).

- файл режется на куски по 256 КБ и отправляется по частям;
- если связь оборвалась, загрузка продолжается с последней подтверждённой части;
- в интерфейсе показываем прогресс и кнопку «Отменить»;
- для приёма файлов — обычная ссылка Storage, которая кэшируется на устройстве.

То есть поведение «случайно сбросил — продолжил с того же места» мы получаем
не от браузера, а от Storage, и оно будет работать так же.

## 6. Спайк на полдня (до основной работы)

Собрать пустую оболочку и проверить на реальном телефоне:

1. GeckoView открывает локальный `index.html` из assets — интерфейс рисуется
   как в браузере (цвета, скругления, шрифты).
2. Включён авиарежим — интерфейс открывается, история из IndexedDB видна.
3. Выбор фото из галереи и с камеры доходит до страницы.
4. `localStorage` и `IndexedDB` сохраняются после перезапуска приложения.
5. Размер APK и время холодного старта.

Если все пять пунктов проходят — идём дальше. Если нет — разбираемся на месте,
пока не поздно.

---

## 7. Что это меняет в общем плане

- Этап «каркас приложения» объединяется со спайком: сразу делаем оболочку
  на GeckoView, а не на WebView.
- Сборка APK появляется уже на первой неделе — с локальным интерфейсом
  и без данных.
- Firebase подключается внутрь веб-части, оболочка об этом не знает.
- Подпись и релиз — в конце, как и планировали.

Время: спайк 0,5 дня, полная оболочка 1–1,5 дня. Дальше — веб-часть и Firebase.
