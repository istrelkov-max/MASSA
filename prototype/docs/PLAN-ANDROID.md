# План приложения massa для Android

## 1. Что уже готово и на что опираемся

Сервер (`server.py`) и веб-клиент дают почти всё, что нужно приложению:

- аккаунты в `accounts.json`, пароли — PBKDF2-HMAC-SHA256 (120k итераций, соль на пользователя);
- сессии-токены на 30 дней;
- `GET /api/sync` — все чаты, сообщения и файлы одним пакетом;
- личные чаты между реальными аккаунтами, непрочитанные;
- `ts` у каждого сообщения (время сервера, клиент показывает в своей зоне);
- фото, видео и файлы на диске `/opt/massa/files/<uuid>`, отдача по `/files/<id>`;
- HTTPS через Caddy на `50-114-115-15.sslip.io`.

Отдельный мобильный бэкенд не нужен: приложение — второй клиент того же API.

## 2. Платформа и распространение

- **Только Android.** iOS не делаем.
- Kotlin, **Jetpack Compose**, Material 3, минимум **Android 8.0 (API 26)**, target 35.
- Архитектура — MVVM + Repository, один модуль `app`.
- **В Google Play не публикуем.** Распространение — APK напрямую:
  - собираем подписанный APK;
  - кладём на наш же сервер: `https://50-114-115-15.sslip.io/app/massa.apk`;
  - на сайте — кнопка «Скачать приложение»;
  - обновления — проверка версии через `GET /api/app/version` и ссылка на новый APK.
- Ключ подписи генерируем один раз и храним — без него обновления поверх
  установленной версии не встанут.

## 3. Что добавить на сервер (0.5–1 день)

1. **Токен в заголовке.** Сейчас сессия в cookie. Добавить приём
   `Authorization: Bearer <token>` наравне с cookie.
2. **Токен в теле ответа** у `POST /api/auth/login` и `/api/auth/register`.
3. **Инкрементальная синхронизация:** `GET /api/sync?since=<ts>` — только новое.
4. **Real-time:** `GET /api/events` (SSE) — сервер шлёт `new_message`, `chat_updated`.
   На 1 vCPU и десятке пользователей дешевле WebSocket.
5. **Пуши (по желанию):** без Google Play FCM работает, но требует
   Firebase-проект. Можно вообще без пушей — тогда SSE, пока приложение открыто.
6. **Раздача APK:** статический файл `app/massa.apk` + `GET /api/app/version`
   с номером версии и ссылкой.

## 4. Экраны

```
AuthScreen      — MASSA, вход / регистрация (почта, пароль)
ChatListScreen  — Избранное, чаты, поиск, меню на всю верхнюю площадь
ChatScreen      — пузыри, фото, видео (Media3/ExoPlayer), файлы, свайп назад
SearchScreen    — люди по имени/почте, свои чаты
NewGroupScreen  — выбор участников из аккаунтов
MembersScreen   — участники группы
SettingsScreen  — аватар, тема, акцент, выход
```

Визуально повторяем веб: серый с голубым отливом, маленькие скругления,
плоские цвета без градиентов, квадратные аватарки, две кнопки вложений
(скрепка — файлы, пейзаж — фото и видео).

## 5. Данные и офлайн

- Локальная база — **Room** (чаты, сообщения, пользователи).
- Старт: есть токен в EncryptedSharedPreferences → `GET /api/sync` → в Room → показ из Room.
- Отправка: сообщение пишется в Room со статусом `sending`, уходит в сеть,
  при ошибке — `failed` и повтор через WorkManager.
- Файлы: метаданные в Room, сам файл — в кэше Coil/Media3.
- Время: храним `ts` с сервера, форматируем в зоне устройства.

| Этап | Что делаем | Оценка |
|---|---|---|
| 1. Каркас | проект, тема, навигация, заглушки экранов | 2 дня |
| 2. Авторизация | вход/регистрация, хранение токена, `Bearer` на сервере | 2 дня |
| 3. Список и чат | Room, sync, пузыри, отправка, время по `ts` | 4 дня |

| 6. Real-time | SSE, уведомления о новых сообщениях | 2 дня |

## 7. Закрытие веб-версии (после отладки)

Сейчас сайт работает — это удобно проверять в браузере. После отладки приложения:

- Caddy перестаёт отдавать `index.html`, `app.js`, `styles.css` — остаются
  только `/api/*`, `/files/*` и страница «скачать приложение»;
- либо сайт отвечает страницей со ссылкой на APK;
- браузерная cookie-сессия отключается, API работает по `Bearer`.

Делаем последним шагом, когда приложение стабильно.

## 8. Что решить до старта

1. **applicationId** — например `app.massa` (после установки менять нельзя).
2. **Ключ подписи** — `keystore` + пароли, хранить в надёжном месте.
3. **Иконка и название** — MASSA, квадратная иконка в текущем стиле.
4. **Нужны ли пуши** — если да, понадобится Firebase-проект (бесплатно).
5. **Домен** — сейчас `50-114-115-15.sslip.io`; для APK не критично, можно оставить.

## 9. Риски

- **Без Google Play** нет автообновлений: пользователь ставит APK вручную,
  и при обновлении Android спросит подтверждение. Это нормально для своего круга.
- **Установка из неизвестного источника** — на телефоне нужно разрешить
  установку из браузера/файлового менеджера.
- **Токен** — только EncryptedSharedPreferences, не обычные настройки.
- **Файлы.** 50 МБ на файл, на VPS свободно ~21 ГБ — при активном обмене
  нужен лимит на пользователя.
- **Один сервер.** При падении приложение показывает кэш и «нет связи».
- **Часовые пояса** уже решены через `ts`; уведомления форматирует клиент.
