# massa — прототип интерфейса

Мобильный (Android) интерфейс мессенджера: чистый HTML/CSS/JS, без сборки,
зависимостей и сервера. Открывается двойным кликом по `index.html`.

Тема по умолчанию — светлая; тёмная включается в настройках.

## Как устроен экран

- Один вертикальный экран — список чатов и «Избранное». Никаких двух колонок.
- Чат открывается **во весь экран**, поверх списка.
- Закрыть чат можно:
  - системным жестом «назад» на Android (через `history`, работает и кнопкой
    «назад» в браузере);
  - **свайпом вправо** по экрану чата (мышью тоже — зажать и потянуть);
  - стрелкой «назад» в шапке чата;
  - клавишей `Esc` на ПК.
- На ПК интерфейс показан в вертикальной «телефонной» рамке, по бокам — полосы.
  На узком экране (телефон) рамка исчезает и всё занимает весь экран.

## Что уже есть

- **Вход и регистрация по почте.** Проверяется только формат адреса
  (`name@mail.com`), письма никуда не уходят. Пароль от 6 символов,
  при регистрации — повтор пароля. Кнопка входа приглушена под фон и
  загорается акцентом только когда поля заполнены правильно.
  Демо-аккаунт: `admin@massa.app` / `123456` (админ, имя — «Админ»).
- **Пустой стартовый список.** После входа в чатах только «Избранное».
- **Поиск = каталог.** Ищет по чатам и «Избранному», а если чата ещё нет —
  показывает людей и группы, которых можно добавить (по имени, `@нику`, почте).
  Плюсик добавляет чат и сразу его открывает. `/` или `Ctrl/Cmd + K`.
  Пока запрос пустой, никого не показываем: люди и группы находятся только
  поиском, списка «все подряд» нет.
- **Админ-аккаунт.** Демо-пользователь — администратор: видит чаты и
  сообщения всех аккаунтов, в списке они подписаны именем владельца,
  в профиле стоит метка «админ». Обычные аккаунты видят только свои чаты.
- **Избранное** — заметки и ссылки «для себя», счётчик в списке.
- **Вложения.** Кнопка-скрепка в поле ввода: фото показываются в переписке
  картинкой (тап — просмотр на весь экран), документы — карточкой с именем
  и размером (тап — скачать). До 25 МБ на файл, большие картинки сжимаются
  до 1400 px, чтобы влезали в браузерное хранилище.
- **Аватарка — только в настройках:** «Сменить фото» в карточке профиля
  (или тап по аватару там же). Картинка обрезается в квадрат 256×256
  и сохраняется.
- **Переписка между аккаунтами.** Личный чат создаётся по аккаунту
  (поиск по имени или почте), оба участника видят его у себя, у каждого
  своё название — имя собеседника, и свой счётчик непрочитанных.
- **Время — с сервера.** У сообщения хранится серверный `ts` (мс), а на
  экране оно показывается в часовой зоне устройства: и в пузыре, и в списке
  чатов, и в разделителях «Сегодня / Вчера».
- **Переписка** — отправка сообщений, история по дням, превью в списке.
- **Участники группы** — тап по шапке группового чата открывает список:
  вы помечены «вы», у остальных видны ники и роли (админ, модератор).
  В личных чатах шапка не открывается.
- **Создание группы** — меню «⋮» → «Создать группу»: название, фильтр
  по людям и выбор участников. Кнопка «Создать» включается, когда есть имя
  и хотя бы один человек. Группа сразу открывается, а в её шапке — участники.
- **Настройки** (меню «⋮» → «Настройки»): профиль, смена фото, тема,
  акцентный цвет и выход. Закрываются стрелкой, `Esc` или системным «назад».
- **Акцентный цвет** — 8 вариантов (медь, янтарь, олива, бирюза, индиго,
  сирень, роза, графит). Перекрашивает **весь интерфейс**: фон, панели, обои
  чата, полосы вокруг телефона, кнопки, пузыри, бейджи, аватары и фокус.
  Базовая тёмно-бурая тема — это просто пресет «Медь». Палитра считается
  из оттенка акцента: тёмный фон и панели получают его подтон, светлая тема —
  светлый вариант того же оттенка. Выбор **сохраняется в профиле** (`user.accent`)
  и в `localStorage`, так что переживает перезагрузку и перелогин; у каждого
  аккаунта свой цвет.
- **Тема — только в настройках**: светлая по умолчанию, тёмная переключается
  там же и запоминается. В шапке кнопки темы нет.
- Состояние в `localStorage`; в меню — выход и сброс демо-данных.

## Где лежат файлы

Вложения не пишутся в `localStorage` вместе с сообщениями. Сначала пробуем
IndexedDB (там файлы любого размера). Если браузер его не даёт (бывает на
`file://`), небольшие файлы уходят в `localStorage` как data URL, а крупные
живут в памяти до перезагрузки — об этом честно предупреждает всплывашка.
При переезде на Firebase это место заменится на Firebase Storage.

## Как открыть

1. Двойной клик по `prototype/index.html`.
2. Либо из папки `prototype`: `python -m http.server 8000` → `http://localhost:8000`.

> Если открывать страницу в предпросмотре редактора или в песочнице,
> скрипты могут быть отключены — тогда кнопки не работают. Нужен обычный браузер.
> Чтобы проверить «как на телефоне», сузьте окно уже 560 px или откройте на телефоне.

## Параметры адреса

| Параметр | Что делает |
|---|---|
| `?demo=1` | войти демо-аккаунтом |
| `?tab=register` | открыть регистрацию |
| `?chat=c-u1` | открыть чат по id |
| `?search=1&q=аня` | открыть поиск с запросом |
| `?theme=light` | светлая тема |
| `?accent=teal` | акцент: `copper`, `amber`, `olive`, `teal`, `indigo`, `violet`, `rose`, `graphite` |

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | разметка: рамка телефона, вход, список, чат, поиск |
| `styles.css` | темы, вёрстка, рамка и полосы, анимации |
| `app.js` | интерфейс: формы, рендер, поиск, настройки, акценты, свайпы |
| `api.js` | **слой данных** — два бэкенда: локальный и HTTP |
| `server.py` | **сервер целиком**: хостинг, API, Firebase, файлы |

## Идентификаторы

Всё в данных адресуется по **UUID v4** — так записи удобно класть в Firebase
как ключи: `users/{id}`, `chats/{id}`, `messages/{id}`.

- `users[].id`, `directory[].id`, `chats[].id`, `messages[].id`, `files[].id`
  (`favorites.id` — тоже UUID).
- Сессия хранится как `{ userId }`, а не по почте.
- Связи — только через UUID: `chat.entryId` указывает на запись справочника,
  `message.file.id` — на файл в хранилище.
- В интерфейсе есть один псевдо-id `'fav'` — это маршрут к «Избранному»,
  сама запись избранного имеет свой UUID.

Данные лежат в `localStorage` под ключом `massa.demo.v4`. Если там лежит
старое сохранение `massa.demo.v3`, оно один раз автоматически переезжает
на UUID: пересоздаются id, сессия перевязывается на `userId`, чаты и
сообщения сохраняются.

## Сервер: server.py (хостинг + API + Firebase)

Всё серверное — **один файл** `server.py`. Он же раздаёт статику, он же API,
он же работает с базой.

```bash
python server.py            # http://localhost:8080
PORT=8099 python server.py  # другой порт
```

Что внутри:

- **Хостинг.** Отдаёт `index.html`, `styles.css`, `api.js`, `app.js` из своей
  папки и файлы из `files/`.
- **API** под `/api/*`: вход, регистрация, чаты, сообщения, участники,
  справочник, поиск, загрузка файлов, сброс демо-данных.
- **`GET /api/sync`** — всё для текущего пользователя одним пакетом: чаты,
  все сообщения, «Избранное» и список файлов. Клиент вызывает его сразу после
  входа, складывает в память и прогревает картинки, поэтому открытие любого
  чата уже не делает ни одного запроса.
- **База — Firebase Realtime Database** через REST. Если Firebase не настроен,
  состояние пишется в `state.json` рядом с файлом, чтобы можно было запустить
  и проверить без аккаунта.
- **Файлы** — в папке `files/` рядом, без ограничения на количество
  (лимит только 25 МБ на один файл).

Подключение Firebase:

```bash
FIREBASE_URL=https://<project>-default-rtdb.firebaseio.com \
FIREBASE_SECRET=<database secret> \
python server.py
```

или вместо секрета `FIREBASE_TOKEN=<id token>`. Путь внутри базы меняется
через `FIREBASE_PATH` (по умолчанию `/massa`). Вся база — один JSON-документ:
`users`, `emails`, `directory`, `chats`, `favorites`, `files`, `sessions`.

Клиент сам выбирает режим: при открытии через `http(s)` он проверяет
`/api/ping` и, если сервер отвечает, работает через него; при открытии файла
двойным кликом остаётся локальный режим на `localStorage`.

## Аккаунты

Аккаунты живут **отдельно от переписки** — в файле `accounts.json`
в домашней папке пользователя сервиса (`/opt/massa/accounts.json`),
права `600`, владелец `massa`:

```
{ "users": { "<uuid>": { email, name, role, salt, hash, ... } },
  "emails": { "почта": "<uuid>" },
  "sessions": { "<token>": { uid, createdAt, expiresAt } } }
```

- Пароли **не хранятся** — только соль и `PBKDF2-HMAC-SHA256`, 120 000 итераций,
  своя соль у каждого. Проверка через `hmac.compare_digest`-совместимое сравнение.
- Сессии — случайные токены на 30 дней, просроченные вычищаются при загрузке.
- Путь можно переопределить: `ACCOUNTS_FILE=/path/accounts.json`.
- Всё остальное (чаты, сообщения, справочник, файлы) — в `state.json` или
  Firebase, без паролей и почт.

## Деплой на Linux

Зависимостей нет — только стандартная библиотека Python 3.7+.

```bash
# 1. файлы на сервер
sudo mkdir -p /opt/massa
sudo cp server.py index.html styles.css api.js app.js /opt/massa/
sudo useradd -r -s /usr/sbin/nologin massa
sudo mkdir -p /opt/massa/files
sudo chown -R massa:massa /opt/massa
```

`/etc/systemd/system/massa.service`:

```ini
[Unit]
Description=massa messenger
After=network.target

[Service]
Type=simple
User=massa
WorkingDirectory=/opt/massa
Environment=PORT=8080
Environment=FIREBASE_URL=https://<project>-default-rtdb.firebaseio.com
Environment=FIREBASE_SECRET=<database secret>
ExecStart=/usr/bin/python3 /opt/massa/server.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now massa
journalctl -u massa -f
```

Снаружи — TLS-прокси (nginx или caddy), иначе cookie сессии пойдёт по
открытому HTTP:

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Host $host;
        client_max_body_size 30m;   # под загрузку файлов до 25 МБ
    }
}
```

`X-Forwarded-Proto` важен: по нему сервер помечает cookie как `Secure`.
Пользователю `massa` нужны права на запись в `/opt/massa` — там появляются
`state.json` и папка `files/`.

Проверить, что поднялось: `curl http://127.0.0.1:8080/api/ping` →
`{"ok": true, "mode": "http", "firebase": true}`.

## API и Firebase

Интерфейс общается только с `window.MassaApi` (см. `api.js`), поэтому данные
можно перенести в облако, не трогая UI.

Внутри два бэкенда с одинаковым контрактом: `LocalBackend` (localStorage,
работает без сервера) и `HttpBackend` (`server.py`), плюс заготовка
`FirebaseBackend` на случай прямого подключения из браузера.

Схема документа в Firebase:

```
/massa/users/{uid}       { email, name, role, salt, hash, avatar, accent }
/massa/emails/{email}    uid
/massa/directory/{id}    человек или группа
/massa/chats/{id}        { name, ownerId, type, people, unread }
/massa/chats/{id}/messages/{mid}  { uid, text, ts, file }
/massa/favorites/{uid}   { id, messages }
/massa/files/{id}        { name, size, type, kind }
/massa/sessions/{token}  { uid, createdAt }
```

Ключи — те же UUID, что и в локальном состоянии.
